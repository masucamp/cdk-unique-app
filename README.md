# AWS マニアックサービス活用アプリケーション

このプロジェクトは、AWSの一般的ではない「マニアックな」サービスを組み合わせて構築したアプリケーションのCDK実装です。

## 選定したAWSマニアックサービス

1. **AWS Comprehend Medical** - 医療テキストから情報を抽出するための自然言語処理サービス
   - 選定理由: 医療特化型のAIサービスであり、一般的なComprehendよりもさらに専門的で利用頻度が低い
   - 活用方法: 医療記録から重要な医療情報を抽出する

2. **AWS Polly Neural Text-to-Speech** - 自然な音声合成サービス
   - 選定理由: 音声合成はAWSのサービスの中でも比較的マニアックな領域
   - 活用方法: 抽出された医療情報を音声に変換して提供する

3. **AWS Step Functions** - ワークフロー管理サービス
   - 選定理由: サーバーレスワークフローの調整に特化したサービスで、一般的なLambdaよりも使用頻度が低い
   - 活用方法: 医療テキスト分析から音声合成までの一連の処理フローを管理

## アプリケーションのユースケース

**医療記録音声アシスタント**

医療従事者が入力した患者の医療記録テキストから、重要な医療情報（診断、薬剤、治療法など）を自動的に抽出し、それを自然な音声に変換して提供するアプリケーション。医療従事者が運転中や他の作業をしながらでも、患者情報を確認できるようにします。

## アーキテクチャ

```
+----------------+     +-------------------+     +------------------------+
|                |     |                   |     |                        |
| S3 Input       |     | Step Functions    |     | Lambda +               |
| Bucket         +---->+ Workflow          +---->+ Comprehend Medical     |
| (Text Files)   |     | (Orchestration)   |     | (Medical Text Analysis)|
|                |     |                   |     |                        |
+----------------+     +-------------------+     +------------------------+
                                                            |
                                                            v
                       +----------------+     +------------------------+
                       |                |     |                        |
                       | S3 Output      |     | Lambda +               |
                       | Bucket         +<----+ Polly                  |
                       | (Audio Files)  |     | (Text-to-Speech)       |
                       |                |     |                        |
                       +----------------+     +------------------------+
```

1. 医療テキストファイルがS3バケットにアップロードされる
2. Step Functionsワークフローが起動
3. Lambda関数がComprehend Medicalを使用してテキストから医療情報を抽出
4. 別のLambda関数がPollyを使用して抽出情報を音声に変換
5. 生成された音声ファイルが別のS3バケットに保存される

詳細なアーキテクチャ情報は [docs/architecture.md](docs/architecture.md) を参照してください。

## デプロイ方法

### 前提条件

- Node.js (v14以上)
- AWS CLI (設定済み)
- AWS CDK (v2)

### セットアップ手順

1. リポジトリをクローン

```bash
git clone <repository-url>
cd aws-maniac-services-app
```

2. 依存関係のインストール

```bash
npm install
```

3. CDKの初期化（初回のみ）

```bash
cdk bootstrap
```

4. アプリケーションのデプロイ

```bash
cdk deploy
```

デプロイが完了すると、入力バケット名と出力バケット名がコンソールに表示されます。

## 使用方法

1. デプロイ後に表示された入力バケットに医療テキストファイルをアップロードします。
   - サンプルファイルは `sample/patient-record.txt` にあります。

```bash
aws s3 cp sample/patient-record.txt s3://<入力バケット名>/
```

2. Step Functionsワークフローが自動的に起動し、テキスト分析と音声合成が行われます。

3. 処理が完了すると、出力バケットに音声ファイルが生成されます。

```bash
aws s3 ls s3://<出力バケット名>/
```

4. 生成された音声ファイルをダウンロードして再生します。

```bash
aws s3 cp s3://<出力バケット名>/<ファイル名> ./
```

## 評価レポート

### メリット

1. **専門分野での高い精度**: Comprehend Medicalは医療テキスト特有の用語や表現を理解するため、一般的なテキスト分析サービスよりも医療情報の抽出精度が高い。
2. **自然な音声合成**: Polly Neural Voiceは従来の音声合成よりも自然な音声を生成でき、長時間聞いても疲れにくい。
3. **柔軟なワークフロー管理**: Step Functionsにより、複雑な処理フローを視覚的に管理でき、エラーハンドリングや再試行ロジックも容易に実装できる。
4. **サーバーレスアーキテクチャ**: インフラ管理の手間がなく、使用量に応じた課金で経済的。

### デメリット

1. **サービスの地域制限**: Comprehend Medicalは一部のリージョンでのみ利用可能。
2. **言語の制限**: Comprehend Medicalは英語のみをサポート（2023年6月現在）。
3. **コスト**: 処理するテキスト量や音声生成量が多い場合、コストが増加する可能性がある。

### 課題と今後の展望

1. **多言語対応**: 将来的に日本語など他言語でのサポートが拡充された場合の対応。
2. **リアルタイム処理**: 現在はバッチ処理だが、リアルタイム音声認識と組み合わせることで、医師の音声入力からリアルタイムで情報抽出と要約が可能になる。
3. **UI/UX改善**: ウェブインターフェースやモバイルアプリの開発による使いやすさの向上。
4. **セキュリティ強化**: 医療情報は機密性が高いため、KMSによる暗号化やIAMによるアクセス制御の強化が必要。
